## Exact owner-requested signup and onboarding

**Latest owner refinement:** The required cloud minimum is verified Email plus Username, Name, DOB and Sex; Mobile alone is optional in first-time onboarding. Units, Height, Current Weight, Activity Level and Goal remain required for full fitness completion. If all cloud fields are complete but fitness is interrupted, a later same-user session may enter Home only after protected local binding/key/encrypted-store safety, then use a truthful completion pill on the **Profile screen** reached from Home TopBar. Bottom roots are now planned as **Home / Workout / Library / Progress**; there is no planned You tab. This is approved documentation policy, while the merged Expo mock still uses You and no real Auth/local gate/pill exists.

**Task 05 owner-approved unified Auth UX:** Existing shared Expo preview stays visually unchanged. Sign Up: Email → OTP → Create Password. Sign In: Email → reveal Password after Continue → `signInWithPassword` → server eligibility → same-UUID local readiness; no normal Sign In OTP or password update. Forgot Password remains separate Email → recovery verification → New Password → Sign In. A valid persisted same-user session bypasses unnecessary Sign In. Sign Up must respond generically: a surviving provisional UUID may complete secure first enrollment only after fresh OTP, a safely deleted provisional identity starts fresh, and a password-complete UUID uses explicit Sign In/Forgot Password without re-enrollment. This remains a production UI/security policy; Task 06A authorizes only an isolated local Auth proof and does not resolve direct Auth password mutation. See [ADR-017](../docs/09-DECISIONS.md), [lifecycle](../docs/27-OTP-FIRST-AUTH-LIFECYCLE.md) and [tests](../docs/08-TEST-PLAN.md).

**Task 06C owner-confirmed Auth addendum:** Forgot Password begins on the Login Password screen: Forgot Password → Confirm Email → six-digit Recovery OTP → Create New Password → Continue → Login with Email prefilled. Show success only after server confirmation, clear recovery-only session and temporary secrets, require new-password Sign In, and never enter Home automatically. The OTP screen requires accessible six-digit entry, numeric keyboard, paste, invalid-code feedback and server-backed resend/expiry/attempt limits without Expo visual redesign. [Task 06C architecture](tasks/auth/local-20261117-strict-auth-architecture.md) treats signup versus recovery purpose separation as an unproven Auth/server boundary; native ordinary OTP still fails strict direct-password protection, so production Auth stays **BLOCKED**.

**Email → OTP → Password** is the fixed UI order, not subject to redesign. Continue **Account Setup (Username required + Mobile optional, same screen)** → **Name** → DOB (**required**) → Sex (**required**) → Units → Height → Current Weight → Activity Level → Goal → **Final Setup (progress circle → done/checkmark → bottom Continue)** → Home. Only show success after verified saves; no ratings/stars/testimonials. **Only Mobile is optional; it is not a separate screen.** Name remains its own screen immediately after Account Setup. Plan encrypted device-local fitness storage and private minimum cloud identity; existing workout sync/backup rules are unchanged.
