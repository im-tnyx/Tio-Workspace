## Decision and evidence boundary

**Select direction 2: a specific additional isolated managed-boundary proof is required.** Managed Supabase Auth with a controlled OTP gateway remains a *candidate*, not a proven architecture. The documented managed Auth config exposes Email provider, `disable_signup`, password controls, Auth hooks and rate settings, but no documented independent `external_email_magic_link_enabled`/Email OTP toggle. The tested GoTrue environment variable is not proof that the managed project accepts it. The Custom Access Token Hook controls **new JWT issuance**; it did not stop a previously issued OTP access token from calling direct `PUT /user` and replacing an existing password. A direct API bypass is a security **FAIL**, irrespective of UI routing or hook success on other paths.

## Required policy and UX preservation

Any accepted design must enforce server-side: six random numeric digits, 10-minute expiry, at least 60 seconds between sends, at most five total sends per normalized email per rolling hour **shared across signup and recovery**, five wrong verifications followed by a 15-minute challenge/account-aware lock, atomic single-use redemption, concurrent verify/resend safety, purpose separation and generic public status/body/timing. Provider IP/project buckets are supplemental and do not replace this ledger. `AUTH-12`, `AUTH-17` and `AUTH-22` remain **FAIL/UNPROVEN**, not waived.

The UI contract stays: **Sign Up** Email → OTP → Create Password → Cloud Profile → Local Onboarding → Home; **Sign In** Email → Continue → Password → `signInWithPassword`; **Forgot Password** Login → Forgot Password → Email → Recovery OTP → New Password → Continue → Email-prefilled Login. A reset must not create or retain an app session or navigate Home. Cloud eligibility and same-UUID encrypted local binding remain separate gates. This report changes no Expo screen, schema, provider setting or email service.
